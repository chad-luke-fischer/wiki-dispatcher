wiki-dispatch

It lives in your terminal and mounts your Obsidian vault. It reads the way you link, packs only the branch that matters, and hands back a deliverable — while its own skills evolve from every run, gated by you.

Most agents treat a vault as a pile of files to search. wiki-dispatcher treats it as what it is: a graph you built by hand, with an index you curated, links you chose, and tags you meant. It traverses that graph on a token budget, cites every note it draws on, and never writes back without asking.

Built on three ideas

Karpathy · LLM Wiki

A wiki as memory, not a transcript

Instead of scrolling back through everything that's ever happened, the agent keeps a small set of pages it reads and writes to directly — closer to notes a person keeps for themselves than a chat log.

 Google Research · WikiSkill

Its instructions improve after every run

After each task, a separate pass looks at what worked and proposes one small tweak to how the agent works next time. Nothing changes until you approve it.

 Nous Research · Hermes Agent

It learns lessons, not complaints

A one-off mistake doesn't get written down as a rule. Only patterns that hold up across multiple runs get promoted into how the agent behaves.

How it works

What it does

Retrieval follows your links

It parses [[links]], aliases, heading links, embeds, inline and frontmatter tags, and the up: / related: links you hide in frontmatter — then resolves them the way Obsidian does, shortest path first. Behind that sits a SQLite full-text index and a weighted graph, cached outside the vault so nothing is added to it.

Retrieval is a branch, not a search result: best-first from a seed over out-links, backlinks, and shared tags, depth-bounded, stopping when the token budget is spent. Explicit links outrank backlinks outrank tag siblings. What comes back is a catalog of paths first, then cited excerpts — so the agent can read the rest on demand instead of loading everything up front.

One branch ≈ 8k tokens by default. Two branches from different seeds beat one deep branch when the ask spans two topics. Depth 3 is almost never worth it; prefer a second seed.

— skills/traverse/branch-extract/SKILL.md

One command in, one file out

wd ask "…" is the whole interface; wd chat keeps a thread. Before it touches the vault it restates your ask as a contract — Kind · Audience · Done-when — infers the deliverable (note, brief, report, outline, table, dataset, Marp deck, JSON Canvas, Mermaid, or a staged wiki page), and picks the traversal shape that fits: topical, broad, categorical, temporal, two-topic, or provenance.

Every markdown deliverable lands in <vault>/_dispatch/ with frontmatter — kind, trace id, the [[sources]] it drew on, a dispatch/<kind> tag — so it joins your graph the moment it's written.

Distinguish what the vault says from what you infer: “The vault says… / I infer…”. If two notes contradict, that is a finding; put it under Contradictions, never resolve it silently.

— skills/deliver/deliver-markdown/SKILL.md

Parallel traversals on a cheaper model

Big asks fan out. A read-only traverser subagent — running on the cheaper worker tier — takes a seed and returns a cited context pack, so three branches can be pulled in parallel without spending frontier tokens on the walking. Three model tiers, any provider LangChain's init_chat_model knows: frontier for synthesis and proposals, worker for traversal and eval runs, cheap for wiki maintenance and judging — a local Ollama model if you like.

Every run logs provider-reported tokens per model and a list-price cost estimate. wd usage --days 7 tells you what the week cost.

Never exceed the configured budget; two smaller packs beat one big one. The catalog is what you cite from.

— skills/traverse/context-pack/SKILL.md

Skills are managed through a ledger

Ask it to show its skills and you get a table grouped by family — name, state, how often each was used, how often patched, how many evals it has. Ask it to add, update, archive, restore, or pin one and it does, through a single ledgered tool. Every mutation records an actor and a reason, with before-and-after snapshots you can roll back to. Nothing is ever deleted; archiving is the only way out.

It refuses to patch a skill it hasn't read this session, and it lints what it writes: no negative tool claims, no incident logs dressed up as rules, no descriptions past the trigger limit.

Write lessons as rules (“Prefer a second seed over depth 3 — depth 3 pulls tag siblings”) not incident logs (“On 2026-09-12 the branch was too deep”). Archive, never delete.

— skills/garden/garden-tend/SKILL.md

One patch at a time, and you approve each

Every run is a trace. Rate the ones that matter, and wd garden evolve runs one iteration of the loop: a Wiki Maintainer root-causes the failing traces into pattern pages; a Skill Proposer reads the pattern index and the acceptance ledger and emits one atomic change; the change is applied to a copy of the library and scored against that skill's evals, baseline versus candidate; the diff is staged as a proposal you approve or reject from the CLI.

Rejected ideas stay visible to the proposer so they are not re-proposed. The wiki never rolls back; skills do. During a task, the agent never reads the pattern wiki at all — giving it access measurably hurt in the research this is built on.

One proposal per iteration · wiki never rolls back · inference agent never reads patterns · rejected proposals stay visible to the proposer · lessons not incident logs · archive not delete · read before patch · every mutation has an actor and a reason.

Uses

Where each ask goes

Each shape of ask routes to a traversal skill, a set of vault tools, and a deliverable kind. These are the routes the operating schema ships with.

The ask names a note, a concept, or an entity. Seed it, pull the branch, cite the catalog.

  • Brief me on Skill Evolution and what it connects tobranch-extractvault_branch→brief
  • What does the vault say about the lethal trifecta?wiki-queryvault_searchvault_branch→note
  • Write up WikiSkill as a report, with the gapsbranch-extractbacklink-trace→report

The ask spans a region of the vault. Read the hubs the human already built instead of searching.

  • What do I know about agent harnesses?hub-findvault_hubsvault_read→report
  • Map this vault for mevault-mapvault_map→note
  • Turn the index into a ten-slide deckhub-find→marp

The ask is a facet, not a topic. Links don't help; tags and frontmatter do.

  • Every concept page with low confidence, as a tabletag-lensvault_tagvault_frontmatter→table
  • Export my active projects as CSVtag-lens→dataset

Time is the axis links don't encode. The append-only log and the daily notes do.

  • What entered the wiki in August?timeline-slicevault_read log.md→outline
  • When did the Hermes page last change, and why?timeline-slicebacklink-trace→note

Two ideas, one deliverable. Find the notes that join them; the interesting bridge is usually a concept, not the root index.

  • How does Hermes relate to WikiSkill?path-bridgevault_paths→mermaid
  • Lay the WikiSkill neighbourhood out on a canvasbranch-extractdeliver-canvas→canvas

Where did this claim come from, and what depends on it? Backlinks are the cheapest audit trail; contradictions are the valuable output.

  • Where did the claim that Hermes has a wiki come from?backlink-tracevault_backlinks→report
  • Lint the vaultwiki-lintvault_mapvault_frontmatter→report
  • File that answer back as a synthesis pagefile-back→wikipage (staged, you commit)

Asks about the agent itself route to the garden family. Reads are free; writes are ledgered.

  • Show me all your skillsgarden-tendskills_list
  • Add a skill that digests the last seven daily notesgarden-tendskill_manage create state=seed
  • Write evals for branch-extractgarden-evalskill_manage write_file
  • Learn from that last rungarden-evolve→ wd garden evolve

Skills

Eighteen skills in four families

Skills teach when and how; the tools do the deterministic work. So a skill patch never changes what the code does — only how the model composes it. That is what makes automatic evolution safe to gate. Each skill carries a PURPOSE.md naming the patterns that motivated it.

Quickstart

Getting started

Python 3.11+. The deterministic commands need no key at all; wd ask, wd chat, and wd garden evolve need whichever provider you put in ~/.wiki-dispatcher/config.toml. Start with the fixture vault, then point it at the real one.

Back to top 
# install
pip install -e ".[anthropic,dev]"     # or [openai] / [ollama]
export ANTHROPIC_API_KEY=…

# a tiny synthetic llm-wiki to try it on
wd fixture ./vault && wd mount ./vault

# no LLM: census, hubs, cited branch under budget
wd vault map
wd vault branch "Skill Evolution" --budget 4000

# dispatch
wd ask "Brief me on Skill Evolution and what it connects to"
wd ask "Lay the WikiSkill neighbourhood out on a canvas" --as canvas
wd chat

# garden
wd skills list
wd garden rate <trace-id> 2
wd garden evolve --skill branch-extract
wd garden pending && wd garden approve <id>
wd usage --days 7
